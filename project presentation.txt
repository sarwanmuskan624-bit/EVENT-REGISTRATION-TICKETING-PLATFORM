# EventHub – Event Registration & Ticketing Platform

## 1. Project Introduction

EventHub is a web-based event registration and ticketing platform. Each user has a separate workspace to create and manage their own events. Logged-out visitors see the general homepage, not a combined list of users' events. Organizers share a unique registration link for an event; attendees open that link, register and receive a digital ticket with a unique Ticket ID and QR code.

## 2. Technologies Used

- **Frontend:** React.js 19, JavaScript, Vite and CSS
- **Backend:** Node.js and Express.js
- **Database:** Supabase (PostgreSQL)
- **Authentication:** Supabase Authentication
- **Payments:** Demo payment simulation only (no real money)
- **QR Tickets:** qrcode.react
- **QR Scanning:** html5-qrcode
- **Deployment:** GitHub Pages (frontend) and Render (backend)

## 3. Main Features

### User / Organizer Workspace
1. Create an account and sign in using Supabase Authentication.
2. View a general public homepage while signed out.
3. After login, view and manage only the events belonging to the signed-in account.
4. Create, edit and delete own events.
5. View registrations for own events, search records and view tickets.
6. View dashboard summaries, reports and export registration records to CSV.

### Attendee Registration
1. Organizer copies and shares a unique registration link for one event.
2. Attendee opens the link without needing access to the organizer dashboard.
3. Attendee submits name, email and phone number.
4. Backend validates the link and details and rejects duplicate registration for the same event/email.
5. EventHub generates a unique Ticket ID and QR code.
6. Attendee can view and print the digital ticket.
7. For a paid event, the attendee can complete a clearly labelled demo payment simulation. No real money is charged.

### Ticket Entry
1. Organizer signs in to their own workspace.
2. Organizer scans the attendee QR code or enters the Ticket ID manually.
3. Backend checks ticket validity, payment status and event ownership.
4. A successful first check-in marks the attendee Present; a repeated check-in is rejected.

## 4. Database

The project uses Supabase PostgreSQL.

**Events**
- id – event identifier
- owner_id – ID of the account that owns the event
- name – event name
- event_date – event date
- venue – event venue
- ticket_price – ticket price
- registration_token – unique token used in the event registration link

**Registrations**
- id – registration identifier
- event_id – related event
- student_name – attendee name
- email – attendee email
- phone – attendee phone number
- ticket_code – unique ticket ID
- payment_status – Pending/Paid project status
- attendance_status – Absent/Present
- created_at – registration timestamp

The exact live column types and constraints are maintained in Supabase. Row Level Security policies and backend ownership checks are important parts of access control.

## 5. How the Project Works

1. A user signs in and creates an event in their own workspace.
2. EventHub stores the event with its owner ID and a unique registration token.
3. The organizer shares the event-specific registration link with attendees.
4. The attendee opens the link and submits registration details.
5. The backend validates the token and attendee data, checks for a duplicate registration and saves the registration.
6. EventHub generates a unique Ticket ID and QR ticket.
7. For a paid event, the attendee may complete the demo payment simulation. It updates the project status only; no payment gateway is contacted and no real money is charged.
8. The organizer scans the QR code or enters the Ticket ID to check in the attendee.
9. The organizer reviews reports and can export registration data.

# Important Interview Questions

**Q1. What is React.js?**

React.js is a JavaScript library used to build user interfaces.

**Q2. What is Node.js?**

Node.js is a JavaScript runtime used to run JavaScript outside the browser, including backend applications.

**Q3. What is Express.js?**

Express.js is a Node.js framework used to create backend routes and APIs.

**Q4. What is Supabase?**

Supabase is a backend platform that provides a PostgreSQL database, authentication and other backend services.

**Q5. What is CRUD?**

CRUD stands for Create, Read, Update and Delete.

**Q6. How does EventHub separate users' events?**

Each event stores an owner_id. Event queries filter records using the signed-in user's ID, and the backend checks ownership for protected operations such as ticket validation.

**Q7. What is a registration token?**

It is a unique token in an event-specific link. The backend uses it to find the one event the attendee is allowed to register for.

**Q8. What is demo payment mode?**

It is a project simulation that marks a ticket as Paid for demonstration. It does not connect to a payment gateway or charge real money.

**Q9. How is the QR code generated?**

I used the qrcode.react library to generate a QR code containing the unique Ticket ID.

**Q10. How does QR ticket validation work?**

The scanner reads the Ticket ID from the QR code. The backend checks the ticket, payment status and event ownership before marking the attendee Present. A repeated check-in is rejected.

**Q11. What is RLS?**

RLS stands for Row Level Security. It controls which users can access or modify database records.

**Q12. Where is the project deployed?**

The frontend is deployed on GitHub Pages and the Express backend is hosted on Render. Supabase provides the database and authentication.

**Q13. What did you learn from this project?**

I learned React, Node.js, Express, Supabase, authentication, CRUD operations, access control, demo payment simulation, QR code generation and validation, reporting and deployment.
