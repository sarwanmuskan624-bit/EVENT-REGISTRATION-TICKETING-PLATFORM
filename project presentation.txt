# EventHub – Event Registration & Ticketing Platform

## 1. Project Introduction

EventHub is a web-based event registration and ticketing platform. Students can explore events, register online, complete a test payment, and receive a digital ticket with a unique QR code. Administrators can manage events, registrations, payments, reports and event entry.

## 2. Technologies Used

- **Frontend:** React.js 19, JavaScript, Vite and CSS
- **Backend:** Node.js and Express.js
- **Database:** Supabase (PostgreSQL)
- **Authentication:** Supabase Authentication
- **Payments:** Demo payment simulation (no real money)
- **QR Tickets:** qrcode.react
- **QR Scanning:** html5-qrcode
- **Deployment:** GitHub Pages (frontend) and Render (backend)

## 3. Main Features

### Student / Public Website
1. Browse upcoming events with date, venue and ticket price.
2. Register with name, email and phone number.
3. Prevent duplicate registrations for the same event and email.
4. Generate a unique Ticket ID and QR code.
5. Complete the demo payment simulation for paid events.
6. View and print the digital ticket.

### Admin Workspace
1. Secure admin login using Supabase Authentication.
2. Dashboard with event, registration, paid-ticket and check-in counts.
3. Create, edit and delete events.
4. Search registrations by student name, email or Ticket ID.
5. View a student's complete digital ticket.
6. Review payment and attendance status.
7. Scan QR codes or manually enter Ticket IDs for validation.
8. Reject invalid tickets and prevent duplicate check-ins.
9. View payment, attendance and event-wise analytics.
10. Export registration records to CSV.

## 4. Database

The project uses Supabase PostgreSQL with two main tables.

**Events**
- id
- name
- event_date
- venue
- ticket_price

**Registrations**
- id
- event_id
- student_name
- email
- phone
- ticket_code
- payment_status
- attendance_status
- created_at
- (No payment-gateway credentials or payment IDs are stored)

Row Level Security (RLS) is enabled. The backend uses its private Supabase service key; it must never be exposed in frontend code or GitHub.

## 5. How the Project Works

1. A student opens the public EventHub website and selects an event.
2. The student submits registration details.
3. The backend validates the details, checks for duplicate registrations and saves the registration.
4. EventHub generates a unique Ticket ID and QR ticket.
5. For a paid event, the student can choose Complete demo payment. The backend updates the ticket status to Paid for project demonstration; no payment gateway is contacted and no real money is charged.
8. The admin can scan the QR code or enter the Ticket ID to check in the attendee.
9. The admin reviews analytics and exports registration data when required.

# Important Interview Questions

**Q1. What is React.js?**

React.js is a JavaScript library used to build user interfaces.

**Q2. What is Node.js?**

Node.js is a JavaScript runtime used to run JavaScript outside the browser, including backend applications.

**Q3. What is Express.js?**

Express.js is a Node.js framework used to create backend routes and APIs.

**Q4. What is Supabase?**

Supabase is a backend platform that provides a PostgreSQL database, authentication and other backend services.

**Q5. What is CRUD?**

CRUD stands for Create, Read, Update and Delete.

**Q6. What is demo payment mode?**

It is a project simulation that marks a ticket as Paid for demonstration. It does not connect to a payment gateway or charge real money.

**Q7. Why is payment signature verification required?**

For this academic demo, the backend updates the payment status through a clearly labelled simulation endpoint. It is not suitable for real payments.

**Q8. How is the QR code generated?**

I used the qrcode.react library to generate a QR code containing the unique Ticket ID.

**Q9. How does QR ticket validation work?**

The scanner reads the Ticket ID from the QR code. The backend checks the ticket, payment status and attendance status before marking the attendee Present.

**Q10. What is RLS?**

RLS stands for Row Level Security. It controls which users can access or modify database records.

**Q11. Where is the project deployed?**

The frontend is deployed on GitHub Pages and the Express backend is hosted on Render. Supabase provides the database and authentication.

**Q12. What did you learn from this project?**

I learned React, Node.js, Express, Supabase, authentication, CRUD operations, demo payment simulation, QR code generation and validation, reporting and deployment.
